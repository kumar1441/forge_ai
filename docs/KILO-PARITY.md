# Kilo Parity

Forge AI is a SolidWorks-panel fork carrying Kilo's chat/agent UX into CAD. This document is a ledger of what is ported from Kilo, how close the shipped behavior is, and what is deliberately out of scope.

**Status key:** `Full` = same behavior; `Close` = same intent, adapted to the CAD host or with known small differences; `Partial` = core behavior present but a documented limitation remains.

**"Where" names symbols** (classes, methods, DOM ids, config keys), never line numbers — line references rot on every rebuild. Everything below was read out of the current source; no behavior is inferred from older documentation.

## 5. MCP integration

MCP is closer to Kilo than earlier documentation claimed, but it is still not complete. `McpBridge` speaks three transports: `stdio` launches a child process with redirected stdin/stdout/stderr and newline-delimited JSON-RPC 2.0; `http` posts to a streamable-HTTP endpoint, accepts **both JSON and SSE** response bodies, and echoes a server-supplied `Mcp-Session-Id` on later requests (`RpcOnServerAsync`); `sse` is the legacy SSE-only transport — a GET event stream with endpoint discovery (`SseConnectAsync`/`SseReaderLoop`/`EndpointTcs`) followed by POST JSON-RPC to the discovered URL (`HttpPostAsync` uses `SsePostUrl`). Request `headers` on both HTTP transports expand `{env:VAR}` / `${VAR}` / `%VAR%` at USE time (`ExpandHeaderValue`); stdio `env`/`cwd` pass through verbatim. OAuth Bearer tokens are injected per request with proactive refresh (`GetOAuthBearerAsync`/`RefreshOAuthTokenAsync`). The handshake is `initialize` → `notifications/initialized` → `tools/list` → `tools/call`; `notifications/tools/list_changed` and `notifications/resources/list_changed` invalidate the cached tool/resource lists (`notification` handling in `McpBridge`), and the host forwards tool changes to the panel as an `mcpToolsChanged` message (`McpBridge.ServerToolsChanged`) shown as a non-blocking toast (`mcpToolsNote`, auto-fades, never steals focus). The default stdio launch is `uvx solidworks-mcp`.

## Known deltas / non-goals

Deliberately not shipped (do not assume Kilo parity here):

- **Subagent limits (still non-goals)** — child agents share one serialized CAD tool path (no parallel SolidWorks mutation; COM serialization is locked ON, not configurable), child sessions are conversation branches (no worktree/filesystem isolation), and roles come from `config.json` `agents[]` plus three built-ins (no agent marketplace). Depth / fan-out / child-turn / result-cap limits are configurable in Settings → Subagents (0 = unlimited); per-child Stop is independent while global Stop still stops the run.
- **Scheduled goals / cron** — no `/goal`; work is run-per-turn only.
- **Codebase indexing** — no repository index; CAD context is a per-session sidecar created by `/init`.
- **Git worktrees / snapshot restore** — revert is conversation-only; the CAD model is untouched. There is no document snapshot to restore, and no git-based worktrees.
- **MCP marketplace / registry install** — servers are added manually in Settings or `mcp.json`.
- **Repo-local `.mcp.json`** — project scope is assembly-keyed (`ProjectKeyForAssembly` → `%APPDATA%\Forge\mcp-projects\<hash>.json`), the CAD analogue of repo-local config; no per-folder `.mcp.json` file is read.
- **Full model pricing data** — `pricing` carries live per-1M prices only where the upstream `/models` feed offers them; elsewhere `pricingUnknown` stays true and the UI says "pricing unknown". No per-model prices are invented (unknown Go ids fall back to the approximate 128k window).
- **Fork / share beyond local** — `fork` is local only (a new sid via `ForkSession`); `/share` is a local file export (`DoShareTranscript`) with no remote link service; `revokeShare` is a stub that reports links auto-expire (it is not wired to any server).
- **Structured streaming parts** — answers are rendered as markdown text, not typed content parts.
- **Compaction threshold range** — both host and Settings clamp the threshold to 1–100 (not Kilo's wider range); `reservedTokens`/`tailTurns` of 0 or negative keep the defaults (`min(20 000, max output)` / 2); protocol-level context usage is approximate for unknown model windows.
- **Throughput caps** — history keeps the newest 30 chats (`saveSessions` slice) with 100 turns each, the follow-up queue caps at 50 (`Follow-up queue is full (50)`), and `historyLoaded` rescue renders at most 30 turns; these are storage/throughput bounds, not Kilo behavior.
- **WatchPaths native file watcher** — `watchPaths` restarts use a 2 s poll timer (`WatchPollMs`/`WatchTick`, `WatchBusy` guard) by design; there is no native filesystem watcher and no `WatchFiles` symbol.
- **opencode-go spend/cost breakdown** — the `usageGo` meters cover percent used, status and reset time (rolling/weekly/monthly); there is no per-model spend or cost breakdown.
- **Anthropic model list** — Anthropic-wire endpoints (the `anthropic` preset and kind-`anthropic` customs) expose no `/models` list; the picker reports one fixed model and the id must be set in `config.json` or a custom model entry.
