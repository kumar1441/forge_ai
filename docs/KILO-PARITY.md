# Kilo Parity

Forge AI is a SolidWorks-panel fork carrying Kilo's chat/agent UX into CAD. This document inventories what was ported from Kilo and its parity status, how the MCP integration works, which features are fork-original (not Kilo ports), and the known gaps versus Kilo.

## 2. MCP integration

The MCP integration is a local stdio-only client. `McpBridge.cs:13-20` documents the stdio transport; `McpBridge.cs:171-183` sets `ProcessStartInfo` with RedirectStandardInput/Output/Error, CreateNoWindow, and UTF-8. The protocol is JSON-RPC 2.0 newline-delimited: `initialize` to `notifications/initialized` to `tools/list` to `tools/call` (`McpBridge.cs:144-154`, `McpBridge.cs:385-396`, `McpBridge.cs:404-449`). The default command is `uvx solidworks-mcp` (`McpBridge.cs:43-44`).

- Config lives at `%APPDATA%\Forge\mcp.json` (`McpBridge.cs:55`, `McpBridge.cs:76-79` ConfigPath; `ForgeConfig.cs:8`).
- `McpConfig{Enabled=true, TimeoutMs=300000, StartTimeoutMs=300000}` (`McpBridge.cs:41-48`); load enforces a floor of 30000 (`McpBridge.cs:66-70`); SaveConfig is a merge-write (`McpBridge.cs:82-95`). The Settings panel MCP-server section writes through this path and takes effect on the next build (`ForgePanel.cs:511-513`).
- `/mcps` is READ-ONLY: `panel.html:1421` routes to host status; Describe/DescribeFull are labeled read-only (`McpBridge.cs:102-117`); the host replies with "running|not running|disabled — cmd args (Ns timeout)" (`ForgePanel.cs:482-485`, `ForgePanel.cs:494-513`). It never starts the server.
- `DescribeFull` returns command + args + enabled + timeoutMs as out-params (`McpBridge.cs:110-117`).
- Multi-part build flow: the router sits at `ForgePanel.Pipeline.cs:5072-5075`; TryRunMcpBuild at `ForgePanel.Pipeline.cs:5721-5767`; IsMcpCreate at `McpBuild.cs:703-727` (explicit "mcp", assembly nouns, 3+-step/ambiguous compounds; drawing-domain + edit-cue exclusions at `McpBuild.cs:686-701`); the agent loop at `McpBuild.cs:902-1160` (function-calling ToolsJson/ToolChoice=auto at `McpBuild.cs:984`, per-turn history resend, 200-iteration breaker at `McpBuild.cs:1000-1008`, text-only reply ends turn at `McpBuild.cs:1022-1051`, unknown-tool/oversize/malformed-args feedback at `McpBuild.cs:1073-1094`); single-shot fallback Run at `McpBuild.cs:755-888`, `McpBuild.cs:898-899` for non-compatible providers.
- Disabled guard: EnsureStartedAsync throws "MCP server is disabled — turn it on in Settings → MCP server, then retry." (`McpBridge.cs:122-123`); surfaced at `McpBuild.cs:784`, `McpBuild.cs:933`; a dead server mid-run restarts once then retries (`McpBridge.cs:411-418`).
- 30s floor: LoadConfig ignores values below 30000 (`McpBridge.cs:67`, `McpBridge.cs:70`); CallToolAsync clamps (`McpBridge.cs:407`); handshake comment at `McpBridge.cs:139`.
- 300s default: TimeoutMs=StartTimeoutMs=300000 (`McpBridge.cs:45`, `McpBridge.cs:47`); call sites pass 300000 (`McpBuild.cs:870`, `McpBuild.cs:1105`); RpcAsync fallback of 60000 applies only when the value is <= 0 (`McpBridge.cs:321`).
- stderr correction: stderr is DRAINED AND DISCARDED, not shown. DrainThread/DrainLoop at `McpBridge.cs:199-200`, `McpBridge.cs:247-251`. Chat sees only curated `McpException` strings (`McpBridge.cs:161`, `McpBridge.cs:187`, `McpBridge.cs:194`, `McpBridge.cs:330`, `McpBridge.cs:368`, `McpBridge.cs:373`, `McpBridge.cs:380`) and `{ok:false}` tool text (`McpBridge.cs:404-448`; 8k + 2k history caps at `McpBridge.cs:445`, `McpBuild.cs:1110`).

## 4. Known gaps vs Kilo

- No OS/desktop notifications. Async events appear as in-chat bifrost/impact cards only.
- Single local stdio-only server. There is no server list and no remote URLs, custom headers, or OAuth.
- `/mcps` is read-only status. It cannot start, stop, add, or edit a server.
- Custom model registration is absent. The picker works from the built-in catalog plus favorites/recents.
- Per-tool Ask dropdowns are absent. Tools use implicit Ask gating with allow/deny rules instead of per-tool dropdown settings.
